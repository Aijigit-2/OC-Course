# ПР-4. Потоки и процессы

## Цель

Сравнить один поток, четыре потока и четыре процесса для CPU- и I/O-задач. Каждый режим запускается три раза, выводится медиана.

## Запуск

```bash
python3 benchmark.py generate
python3 benchmark.py cpu
python3 benchmark.py network
python3 benchmark.py memory
```

`generate` создаёт 10 млн чисел в `numbers.txt`. Файл исключён из Git через `.gitignore`. В `urls.txt` уже есть 20 URL; сетевой тест требует доступ в интернет.

## Результат контрольного запуска

CPU, 10 млн чисел, 3 логических CPU:

```text

```

Сеть, 20 URL:

```text

4 потока             12.624    3.47x
```

Время на другом компьютере и при другой сети отличается; одинаковая контрольная сумма подтверждает корректность вычислений.

## Вывод

Для короткой CPU-операции над списком Python потоки и процессы проиграли из-за GIL и стоимости создания работников. Для сетевых запросов потоки ускорили работу в 3,47 раза: во время ожидания сети GIL освобождается. Процессы тоже помогли, но имеют большие накладные расходы.

**Почему 4 потока не ускорили CPU-сумму?** GIL допускает исполнение Python-байткода только одним потоком процесса.

**Почему изменение списка процессом не видно родителю?** После `fork` у процесса отдельное адресное пространство; обычный список не является общей памятью.
