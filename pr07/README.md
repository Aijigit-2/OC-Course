# ПР-7. Межпроцессное взаимодействие

## Цель

Реализовать калькулятор через FIFO и Unix-сокет, сравнить `shared_memory` и `Pipe`.

## FIFO

В двух терминалах из `pr07`:

```bash
# терминал 1
python3 fifo_server.py

# терминал 2
python3 fifo_client.py '2 + 3 * 4'
python3 fifo_client.py '(10 - 4) / 2'
```

Сервер создаёт `/tmp/os_calc_request` и `/tmp/os_calc_response`, удаляет их при выходе. Калькулятор разбирает выражение через AST, а не небезопасный `eval`.

## Unix-сокет

```bash
# терминал 1
python3 socket_server.py

# терминал 2
python3 socket_client.py '2 + 3 * 4'
python3 socket_client.py '(10 - 4) / 2'
```

Путь сокета — `/tmp/os_calc.sock`. Каждый клиент обслуживается в отдельном потоке. Остановка сервера: `Ctrl+C`.

## Сравнение скорости

```bash
python3 shm_benchmark.py --count 10000000
# быстрая проверка:
python3 shm_benchmark.py --count 1000000
```

Контрольный запуск на 1 млн `int64`: `shared_memory` — `0.0816 с`, `Pipe` — `0.1121 с`; обе контрольные суммы равны `499999500000`. Результат на другом компьютере отличается.

## Вывод

FIFO и Unix-сокеты позволяют обмениваться сообщениями между независимыми процессами. Сокет поддерживает нескольких клиентов и двусторонний диалог. Общая память быстрее для большого массива: данные не копируются через очередь сообщений, но доступ к ним при параллельной записи требует синхронизации.

**Когда Pipe удобнее?** Для потока небольших сообщений и простого родитель–потомок взаимодействия, когда синхронизация уже встроена в протокол.

**Почему важно освобождать ресурсы?** Именованные сегменты и файлы IPC могут остаться после аварии и мешать следующему запуску.
